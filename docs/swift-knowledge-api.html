Admission Copilot

Swift Knowledge API

A public endpoint that renders the Nigerian admissions catalogue as a single Markdown document, for upload to the Swift Agents knowledge base.

GET https://<your-domain>/api/swift/knowledge?download=1
Endpoint Document Catalogue status Freshness Safety rules Uploading Limits

Endpoint

One route, no parameters that change the content. Each fetch is generated from the live catalogue, so a current copy is always one request away. Drop ?download=1 to read the document in a browser instead of saving it.

MethodGET
AuthenticationNone. Public by design.
Query parametersdownload (optional) — 1 forces a save as a file
Request bodyNone
Response200 OK, a UTF-8 Markdown document
Saved filenameadmission-copilot-catalogue.md

It is public deliberately. Everything it returns is already public admissions information, sourced from the JAMB IBASS e-brochure and each institution's own bulletin. There is no student data, no session data, and no credential of any kind in the response. Whether it needs to be public is a separate question, answered under Uploading.

Response headers

Content-Type: text/markdown; charset=utf-8
Cache-Control: public, s-maxage=3600, stale-while-revalidate=86400
Content-Disposition: inline; filename="admission-copilot-catalogue.md"

Content-Disposition is attachment instead of inline when download=1 is passed. The filename is the same either way.

The document

Four parts, in this order:

  • Header — generation timestamp and catalogue status
  • Usage and safety rules — constraints the agent is instructed to follow
  • Institutions — every institution held, grouped under a ### <State> heading
  • Programmes — programme records with their requirements

Institutions — complete

Every institution in the catalogue appears, grouped by state:

### Lagos
- University of Lagos (Federal University) — 62 programmes listed
- Lagos State University (State University) — 48 programmes listed

Complete by design, and an institution with no programme detail still appears. The underlying query is a LEFT join, so a school the catalogue knows about but holds no programmes for is listed with a count of 0 rather than omitted.

Programmes are capped at 500.

When the catalogue exceeds that, the document says so in its own text and instructs the reader that a programme absent from it is outside the sample, and not evidence that the institution does not offer it. School-level questions are answered completely; programme detail beyond the cap is not in the document at all.

Programme entries

Each entry carries its own source link:

## Nursing Science — University of Lagos
Department: Nursing
Status: ...
UTME subjects: ...
O-level requirements: ...
Direct Entry requirements: ...
Official remarks: ...
Source: https://...

The Official remarks label is not cosmetic. Only a mirrored IBASS row carries IBASS's own words, so the local sample's text is labelled Note instead — crediting it to JAMB would misattribute it.

Catalogue status

The header states which catalogue backed the document:

Status lineMeaning
JAMB IBASS mirrorThe national catalogue was read.
sample fallback onlyThe database was absent or unreachable; a small local sample was served instead.

Treat sample fallback only as a degraded document.

The sample is a handful of institutions, not a national list, so answers drawn from it are not representative. It is served so the endpoint never fails outright, not because it substitutes for the mirror. Refresh the crawl once the mirror is back.

Freshness

Route revalidation3600 s
Edge caches-maxage=3600, stale-while-revalidate=86400
Authoritythe Generated: timestamp inside the document

Use the Generated: timestamp rather than the time of the crawl. A response can be served stale for up to 24 hours while it revalidates, and a cached body keeps its original timestamp, so that value is the honest answer to how old the document is. The catalogue behind it is refreshed by a separate scheduled sync job, which is what moves the timestamp forward.

Safety rules carried in the document

The document instructs the agent to:

  • Cite the source URL for any programme requirement, and never claim a course is available, or a requirement current, without it
  • Direct students to verify fees, deadlines and portal screens in the current JAMB IBASS record and the institution's own bulletin
  • Never tell a student to pay through a forwarded link — always the official portal, opened by the student
  • Never request, repeat, or handle an OTP, password, PIN, card number, or account credential
  • Say so when a question cannot be answered from a cited official source, and offer a counselor handoff

Automated eligibility verdicts are out of scope.

Those are produced only by the in-app eligibility checker, which works from reviewed rules. The document states plainly that only that checker may present a reviewed automated verdict. The agent should not read requirements out of this document and then declare a student eligible or ineligible.

Uploading

  1. Save a current copy: curl -OJ 'https://<your-domain>/api/swift/knowledge?download=1'. The -OJ flag takes the filename from the response header, so you get admission-copilot-catalogue.md. Opening the URL in a browser works too.
  2. Upload that file to the Swift Agents knowledge base.
  3. Set the agent's instructions to treat admissions and course-discovery questions as in scope.
  4. Re-upload after each catalogue sync. Nothing pushes an update.

Steps 2 and 3 are separate settings. The uploaded file gives the agent facts; it does not widen what the agent is willing to answer, so a narrowly scoped instruction set will keep deflecting admissions questions even with the catalogue uploaded.

Does the endpoint have to be public?

Not necessarily, and the answer changes what you deploy.

If you do the uploading yourself, the endpoint can stay off the public internet entirely — run it locally, or put it behind your normal authentication, and upload the file you save. A knowledge base that ingests files needs a reachable file, not a reachable URL. This is the safer arrangement, because the endpoint queries the database on every cache miss.

If Swift does the integration, they need a URL they can fetch, which means public and unauthenticated as documented above.

Decide before deploying. Adding authentication later is easy; withdrawing a public endpoint that has already been crawled and indexed is not.

Watch the timestamp

An uploaded file is a snapshot and stays exactly as uploaded. Check the Generated: line before uploading — it is the only thing that distinguishes a stale copy from a fresh one.

Known limits

  • Manual refresh. Nothing pushes an updated document into the knowledge base. The uploaded file is a snapshot until somebody replaces it, so a stale upload serves stale answers, and the Generated: line is the only warning.
  • 500-programme cap. School-level questions are complete; programme-level depth beyond the cap is absent.
  • No per-institution drill-down. A /api/swift/knowledge/<institution> route returning one school's full programme list does not exist yet.
  • No fees, deadlines, or portal screens. Excluded on purpose — they change per session, so the document routes students to the official source instead.
  • Markdown, not JSON. Intentional: the knowledge base reads text, and a JSON body would present it with syntax rather than sentences. It also keeps the upload auditable — you can read exactly what the agent was given.
  • No rate limiting. The hour-long edge cache absorbs this in practice, but a cache miss reaches the database.
